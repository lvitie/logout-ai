Rules (agent team; AGENTS.md also applies):
- Output is read by another model: terse bullets, no prose, no restating inputs, stay under the word cap.
- Perforce only, no git. Work goes in the task CL: `p4 edit -c <CL>` / `p4 add -c <CL>`, including new review documents. Reopen task-required files with `p4 reopen -c <CL>`. Leave submission to the coordinating Producer/user after review; routed agents never submit, revert, shelve, sync, or clear read-only bits (AGENTS.md P1; Tools/AgentTeam/PLAN.md).
- Nothing is protected: you may edit any file, including ones in user_opened.txt. Moving files between changelists is allowed: `p4 reopen -c <CL> <file>` (e.g. Unreal auto-adds new assets to the default CL; move them into the task CL yourself). A file open in another numbered CL may be edited in place or reopened into the task CL if the task needs all its files in one CL.
- Standing user approval: assetgen views, Unreal imports, level changes, design decisions, and starting or restarting the editor (./start_inferno.sh). Do not end with STATUS: GATE for these; decide, record the decision in your hand-off, and proceed. GATE only for submit/revert/shelve (forbidden) and paid/partner APIs.
- Engine source changes are allowed but must be merge-friendly: wrap every edit in `// INFERNO - <task id> <short reason>` ... `// ~INFERNO` (comment out replaced engine lines inside the block instead of deleting them; new files get a `// INFERNO - <task id> <reason>` header line), keep edits minimal and local, prefer a project-side fix when equivalent, and log each change in `docs/ENGINE_CHANGES.md` (file, symbol, why, task id, CL).
- Build ONLY with `./build_inferno.sh` from the workspace root (it runs UnrealBuildTool inside the distrobox container; direct `dotnet UnrealBuildTool.dll`, `Build.sh` or `RunUAT.sh` on the host fail on NixOS). Package with `./package_inferno.sh`, start the editor with `./start_inferno.sh`. Never use a host-side UBT build log as evidence.
- Animation work: first read docs/ANIMATION_FEEDBACK.md (user feedback = acceptance criteria) and the reference footage notes in Inferno/Saved/Reference/LotF2/README.md.
- Animation work may modify or add levels: build a new test gym map (e.g. under /Game/Inferno/Maps/Gyms) whenever one is needed to author or verify animations; no approval needed.
- Licensing: SourceImages-derived output stays in Saved/ or /Game/Inferno/Generated; no paid/partner API nodes.
- Editor and GPU are shared: no assetgen during an editor import; mesh stages at 1536 voxels need the editor closed. Save editor work before finishing.
- No repeated work: before capturing, encoding, building, or generating anything, check whether a valid result already exists (Inferno/Saved/AgentTeam/*/packet, replays, logs, earlier tasks). Reuse it unless the assets or code it depends on changed since. Never re-capture footage that already passed; capture only what changed, once, then move on. Keep tooling work minimal and report visible in-game results first.
- Tests and builds: if a suite or build already passed and neither the code nor assets it covers changed since (check p4 opened/diff and timestamps), do not re-run it; cite the earlier result. Re-run only the affected tests after a change, and the full suite once before finishing.
- Editor control: call the Unreal MCP server directly through the mcp__unreal-mcp__* tools (list_toolsets, call_tool). Do not write your own HTTP/RPC wrappers around it. Fall back to a script only if the MCP tools are unavailable or the server is down after one retry; note that in your report.
- Never end your turn while waiting for background work ("I will pick up when they finish"): the run is torn down after your result and everything you started dies (exit 143). Start long jobs detached (setsid nohup ... &), then wait inline in the foreground with a bounded `until [ -f done-marker ] || [ $((SECONDS-start)) -gt 540 ]; do sleep 5; done` loop (max ~9 min per call), repeating the call until the job finishes. Only then write your report.
- Editor startup: before launching any editor, check `pgrep -x UnrealEditor` and `ss -ltn | grep :8000`; if one is running, use it through its MCP server (port 8000) and never start a second one or restart it unless it crashed. If you must start one, start it detached and wait inline in bounded loops. A normal start takes under 5 minutes; startups sometimes hang for hours for no known reason. If the log (Inferno/Saved/Logs/Inferno.log or your own log) shows no "Engine is initialized" and no new line for 5 minutes, kill that editor by PID (a hung start has no PIE, so `kill -9` is fine; never pkill -f) and start it again, up to 3 tries. Only report BLOCKED after 3 failed starts.
- Parallel work: other team tasks may run at the same time (research, reference search, asset generation) while you work. Stay inside your task scope: do not edit files opened in another changelist (`p4 opened -a` shows who has what) unless your task requires it, do not restart or close the shared editor if another task may be using it, and keep ComfyUI/assetgen off the GPU while the editor does captures unless free VRAM is at least 9 GB.
- Log hygiene: your work must not add Output Log warnings or errors in PIE or on editor load. Before finishing, grep the log for new Warning/Error lines caused by your assets or code (e.g. "Invalid Bodies : Make sure collision is enabled or root bone has body in PhysicsAsset") and fix their cause; do not leave them for later. t030/A2b: the chain skeletal meshes spawn without a PhysicsAsset body on the root bone, fix that.
- No hot reload: never build C++ while the editor is running (no `-ModuleWithSuffix`, no Live Coding). It crashes the editor (CoreUObject "Cannot replace existing object of a different class" on BP_Schiavo's InfernoActionComponent). Close the editor first (`./quit_inferno.sh`), run `./build_inferno.sh`, then start it again.
- Leases: take `editor` (and `gpu` for GPU jobs) with the team lock command from the Shared resources section before starting or using the editor, and unlock as soon as you close it or stop needing it.
- One editor total: never start an Unreal editor on any project (including /mnt/games/GASP_staging) while another editor/commandlet or a GPU job is running. Check editor/commandlet processes, MCP listener and ownership before launch; check `nvidia-smi --query-gpu=memory.used,memory.total --format=csv` and require at least 9 GB free for GUI/render work. Headless UnrealEditor-Cmd also counts (AGENTS.md E2; docs/SELVA_NEXT_ROUNDS_PLAN.md E: overlap caused Vulkan OOM).
- Performance: measure and record only. Do not optimize or fix perf problems unless a task explicitly says so; report numbers and regressions (e.g. a frame-time spike you caused) and move on.
- Never report BLOCKED for something already approved above: closing, restarting or killing the editor (`./quit_inferno.sh`; never kill during PIE), builds, tests, moving files between CLs. Decide, do it, and continue. If an editor is open and you need it closed for headless tests or builds, close it yourself. BLOCKED is only for things you truly cannot do (missing credentials, paid API, forbidden p4 submit/revert/shelve).
- Editor shutdown: never SIGTERM/kill during PIE (Chaos exit assertion). Use `./quit_inferno.sh`: stop PIE and verify ended -> save -> Python cleanup -> QUIT_EDITOR -> verify process exit/log and launcher status. Wrapper status 0 does not establish editor exit code. Save/cleanup failure or unknown PIE kills nothing; force only hung/crashed editors with no live PIE, TERM/KILL after timeout. Direct File > Exit/raw QUIT_EDITOR bypasses the tested Python cleanup mitigation (AGENTS.md C5/C6/E1; quit_inferno.sh; Tools/AssetGen/editor_shutdown.py; t094 packet).
- After an editor crash: do not start a new editor until the old one is fully gone. A crashed editor can take minutes to write its crash report while still holding the GPU. Wait (bounded loop, up to 5 min) until `pgrep -f "UnrealEditor|CrashReportClient"` is empty and nvidia-smi memory.used is below 3 GB; if it is still there after 5 minutes, kill it by PID (kill -9; a crashed editor has no live PIE), then start the new one. Two editors at once is what triggers the Vulkan out-of-memory crashes.
- Review captures must be readable: the user found rendered videos very dark. When recording clips or stills for a packet, set a fixed exposure (disable eye adaptation or use manual exposure) and add a neutral fill light or use a lit gym so the character and silhouette are clearly visible; check one frame before encoding the full clip. Do not spend extra rounds on it for existing footage.
- ComfyUI VRAM: ComfyUI servers keep models loaded after a job (the 3D one on port 8189 held 11 GB idle and blocked every other GPU task for an hour). When your generation jobs are finished, release it: `curl -s -X POST http://127.0.0.1:8189/free -H 'Content-Type: application/json' -d '{"unload_models":true,"free_memory":true}'` (also port 8188 for the txt2img server). Do this before ending your stage and before any GPU or editor capture work.
- Screenshots with ImageMagick: `import` (X11 screen capture) BEEPS on every capture unless you pass `-silent` (the user hears it). Always use `import -silent ...`, or capture through the editor/MCP/ffmpeg instead. Never trigger the terminal bell (no `echo -e "\a"`).
- GUI editor hangs (known, seen 2026-10-14 and 2026-10-16: a GUI start stops logging at module load, low CPU, GPU idle in P8, sometimes for hours; cause unknown, possibly needs a reboot): after your 3 killed starts do NOT report BLOCKED. Fall back to the headless route: `UnrealEditor-Cmd Inferno.uproject -ExecCmds="py <your_repl_server.py>" -unattended -nullrhi -nosplash -stdout -ModelContextProtocolPort=8011` inside distrobox with the file-polling python REPL pattern (see Inferno/Saved/AgentTeam/t042/repl_server.py and the user memory note editor-gui-hang-after-kill): PIE, navmesh, level and asset work, automation tests and traces all work headless. Only rendered frames (lit captures, videos, screenshots) need the GUI editor: list those as PENDING captures in the hand-off with exactly what to capture, finish everything else, and do not fail the task for them. The Producer will re-run the captures when the GUI editor works again.
